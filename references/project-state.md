# 团队状态与续接

每支团队独立保存；Skill 文件夹仅放通用规则和匿名化案例笔记。

`project-state.md` 至少在相应信息出现后记录：
- 届次、组别、学校/赛区、赛道、阶段与材料版本。
- 队员角色/可投入时间、导师候选或已确认导师；敏感联系方式按需另存。
- 研究问题、总体、地理与时间范围、资源与预算、当前截止日期及其出处。
- 选题对应的官方政策证据卡、核验状态；导师讨论日期、真实反馈、处理结果、定题状态及修改记录。
- 校内报名/选拔/交稿、学校推荐与全国各赛段期限分别记录出处、核查状态、负责人、团队提前完成日及回执；校内未核时不宣称资格安全。
- 报告页数口径、模块预算、当届硬性限制及视觉风格约定（主色、类别颜色、字体和图表规范）。完整报告默认硬性验收正文45–55页、全册60–80页；记录实际正文起止物理页、正文/全册页数、渲染工具、版本/哈希和验收结论，有据例外单列。
- 报告用户确认状态：未提交审阅 / 待用户确认 / 用户已确认 / 实质修订待重新确认；仅在确认发生后记录用户原话、时间和对应报告版本。PPT启动状态必须依赖这一记录，不能把“继续”自动改写为已确认。
- 各阶段交付物位置、版本、草稿/待核实/通过/需修改状态、未通过条件、负责人及复核记录；报告默认Word，其他赛规格式差异单列待办。
- 校内期限未知时的提前1–2个月暂定计划、团队偏好与官方基准日；明确区别真实截止。
- 合成数据（如有）的用途、来源标识、生成记录及与真实数据的隔离位置；文件制作的工具方案和实际可用性。
- 定题前价值预审记录：候选版本、检索日期及来源、通过/待核验/未通过、判断理由、补证据动作；用户选中方向与价值通过分别记录，缺少预审时先补审再推进。
- 研究价值证据卡：已知基线与来源、未解决问题、不同结果的决策影响、取证设计、选题潜力验收及报告实际贡献验收；共识复述与模拟预设不标通过。
- 核心结果不显著时的问卷设计专项检查、数据/样本/方法诊断、具体缺陷证据、修订与复测/重采记录；未查项明确标待核实。
- 用户已确认的决策、确认时间、仍待验证的假设。
- 本轮已完成、审核结论、未解决问题、依赖关系与下一项具体动作。
- 本团队资料根目录映射（如 reports/videos），不得写到分享版 Skill。

`rules.md` 每项记录规则内容、适用届次/组别/赛段/赛区、来源URL或文件及页码、发布/核查日期、官方/校方/方法建议分类、是否已核实。冲突不静默覆盖，记录取舍依据。

`evidence.md` 建立主张—来源—位置—用途关系；数据另记采集时间、版本、授权范围、清洗记录。图表与报告结论引用同一版本。保留“尚未取得原始数据”等负面状态。

`reviews.md` 记录被审材料版本、问题位置、影响、修改方案、复核结果。只复核改动及其依赖，不每轮要求团队全部重交。

收到“继续”时先报告所续接的阶段与上次未完事项，然后动手。用户更换团队时创建或选择新项目，不继承上一团队身份、数据和审批。
