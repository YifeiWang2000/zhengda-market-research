# 报告、提交与复盘

## 报告

默认交付实际可编辑Word文件（.docx），不要求导出PDF。成品清单、阶段完成条件与格式差异处理见[交付约定](delivery-contract.md)。核查DOCX能打开、目录/页码/表图/字体正常；无法验证时明确范围，不能用聊天文字代替文件成品。

先按当届当赛段模板和评分表组织；无正式模板时按[写作框架与论证](report-writing-framework.md)选择适配题型的章节。服务诊断与方案验证类推荐八章框架，其余题型按决策任务调整，不固定所有项目的章数；页数必须满足下述硬性验收。

摘要交代问题、真实调查范围与方法、主要发现、具体建议和特色，所有数字必须回溯正文。背景资料与本团队发现分开；文献综述围绕研究缺口，不为字数堆资料。调查方案与实际执行差异如实写入。

结果章节按研究问题排列，模型作为工具；图表明确单位、时间、来源、样本量/分母与统计口径，避免3D装饰遮盖差异。定性引语可回到匿名记录；说明访谈反例。建议写给明确行动者，给依据、行动、成本/约束、优先级与可评估指标；未验证的商业假设标清。

附录按规则和研究需要放调查工具、抽样细节、变量字典、必要过程记录与代码说明。不要把直接身份信息、未授权受访者照片、联系方式自动放进公开附录。

## 报告篇幅硬性验收

**完整报告必须同时满足正文45–55页、全册60–80页（含端点）**。这是本Skill的硬性交付条件，不是官方页数规定；正式研究、合成数据演示及技能完整性测试均适用。仅做提纲、阶段章节或明确要求的短稿时可交局部成果，但必须标为局部草稿，不能宣称完整报告或报告阶段通过。

正文指研究背景起至结论/建议/局限结束，不含封面、摘要、目录、参考文献及附录；全册包含这些前后置部分。正文起止处应设置清晰分页边界。使用实际DOCX打开或渲染的物理页序计数，不以预估字数、目录字段、文件元数据、手工页码或预设分页符数代替。附录若另册，报告正文册与附录册逐册计数后合计，重复封面不重复充数。

执行顺序：
1. 写作前列各模块预算并核对合计，确保正文与全册同时落入范围。
2. 完成实质内容后按正常可读字号、行距、页边距排版，更新目录并实际打开/渲染。
3. 在项目reviews.md记录文件版本或哈希、渲染工具、正文物理起止页、正文页数、全册页数、逐页检查结果与验收结论。无法实测页数时标“待验收”，不得宣布通过。
4. 任一范围不满足时继续修订；缺证据则如实列明缺口并交草稿，不能通过重复内容、放大字号、拉大行距、空白页、无关图表或虚构材料凑页数。数字达标也不能替代内容质量审核。
5. 自检通过后交给用户检查，状态为“待用户确认”，等待确认才能进入PPT阶段。后续改动导致重新分页时重做页数验收。

先核查适用赛规及模板：如已核实的官方要求与本范围冲突，明确报告冲突、来源及按官方要求采用的页数，不静默豁免；用户明确要求不同篇幅时记录其原话和新验收范围。除此之外，不得因时间、token、模拟数据或“简洁优先”自行降低标准。

已读PDF实例：R002低空行业49页；R071双减60页；R007咖啡62页；R072文创63页；R004宝妈64页；R003水饺65页；R008小语种77页。样本文件约40–80页，较多约60–65页；R003/R004等缺正文提及的独立附录，不能把文件页数当完整提交包页数，也不能据此推定本科组规定。

以下是模块分配建议；可以调整各模块，但最终正文45–55页、全册60–80页的合计必须同时通过验收，不应把模块上限全部相加：

| 模块 | 建议页数 | 回答的问题 |
|---|---|---|
| 封面、摘要、目录 | 5–8（摘要通常1–2） | 做了什么、关键发现是什么 |
| 背景、政策依据、研究问题 | 3–5 | 为什么研究，研究边界是什么 |
| 文献、理论与研究思路 | 3–5 | 已知什么，还缺什么证据 |
| 调查方案 | 5–7 | 对象、抽样、样本量及调查工具如何设计 |
| 实施、预调查与质量控制 | 4–6 | 如何得到数据，如何修改、清洗，有何限制 |
| 样本、现状与群体差异 | 5–7 | 当前情况如何，哪些人不同 |
| 核心问题深入分析 | 12–16 | 关键问题、相关因素、细分需求与解释 |
| 结论、建议/方案、局限 | 6–9 | 谁应做什么，依据与适用边界是什么 |
| 参考文献 | 1–3 | 实际使用了哪些来源 |
| 附录 | 5–15或按规则另册 | 问卷、访谈、编码、补充结果等追溯材料 |

模块可合并。优先把正文约一半留给深入分析与建议；产品开发/营销类可多留方案页，政策态度/需求类可多留群体差异和解释页。模型公式、软件输出、重复图文不能挤占实质发现。

主线：现实矛盾→研究问题→调查设计与执行→可信证据→现状和差异→解释及边界→有依据的行动。每个分析小节完成“具体问题—数据结果—意义与限制—后续决策”，不按软件或模型清单机械分章。

案例结构供选择：
- 产品开发型（R003）：竞品痛点→消费者偏好与差异→新品组合→生产及推广可行性。
- 品牌营销型（R004）：品牌诊断→目标群体→购买相关因素与细分→渠道/内容偏好→营销方案。
- 需求客群型（R072）：市场关注点→认知和购买现状→意愿相关特征→产品属性偏好→客群→建议。

结构可借鉴，数值和因果解释不能移植。价格重要不直接推出降价，仍需具体人群、产品情境、可接受价格及成本证据。问卷设计时就规划研究问题与报告章节，避免回收后才发现缺题。

封面、正文版式与图表配色制作或审核时读取[视觉风格](report-visual-style.md)。

## 研究价值验收

报告必须交代“已有知识—未解决问题—本研究新增证据—决策影响”，并与选题阶段的研究价值证据卡对应。只重复充分确立的公认共识，或把模拟预设关系重新分析出来，研究价值不通过。新的地名、比例、图表、模型或达标页数都不能单独替代实际贡献。结果不显著时必须附可追溯的问卷设计检查结论，不能仅用局限段落带过；诊断与修订规则见[实施与分析](data-analysis.md)。

篇幅通过、内容证据通过、研究价值通过和用户确认分别记录。报告可以作为未通过的草稿交审，但不得称完整市场研究已通过；合成演示明确写为流程测试，不能借模拟性质豁免真实市场价值验收。

## 交叉审核

核对摘要/正文/图表/PPT/讲稿的样本数、日期、变量、模型结果和结论一致；图表对应同一问卷版本，类别数、图例颜色、比例与分母逐项对照；方案示意图与真实实施记录分开标注，不能用概念效果图证明活动已经发生。参考文献能找到原文，引用位置确实支持主张。若规则要求匿名，同时检查封面、页眉、文件属性、图内校徽、致谢、文件名、视频背景等泄露位置。

按评分项建立证据定位表；分值仅使用已确认适用评分表，给分时说明是模拟评审估计。先改真实性、研究设计、逻辑与结论边界，再润色；不得通过编访谈、套别队样本、改换地名来完善报告。

## 提交

在相应赛段单独核对报名资格、导师与成员登记、材料版本、篇幅、命名、文件格式、附件、匿名、视频时长/分辨率/大小和截止日期。未知规格列待核，不凭往届视频推断本届限制。

生成可预览的最终包和逐项核对结果。上传、发送和正式提交仅按用户明确授权执行；失败保留已完成包与失败原因，不反复提交造成重复记录。提交成功须依据回执/页面状态，不以按钮点击认定。

## 复盘与分享

记录评委原话来源、实际失分点、修改与验证结果，分清评委意见、团队推断和一般方法。可复用内容写成匿名经验；团队私有数据和原始作品不打入分享版 Skill。不能把单次评委偏好变成永久规则。另一个团队使用时重新核查学校、赛区、赛段与资源条件。
